## הבעיה
היום הספקים מדפיסים טבלאות, עוברים בין הגנים ואוספים חתימות של גננות בכתב יד. הטפסים מגיעים לחברת אריאל, ושם מקלידים ובודקים אותם ידנית מול ההתקשרויות והתקרות. מדובר בכ-100 טפסים בחודש, בתהליך איטי, חשוף לטעויות וקשה לבקרה.

## הפתרון
מערכת אחת לשלושה סוגי משתמשים:

| משתמש | מה עושה במערכת |
|---|---|
| **ספק** | נכנס עם מספר ספק וקוד חד-פעמי לנייד, מסמן מפגשים ביומן לפי גן, ושולח דיווח חודשי מרוכז |
| **גננת** | מקבלת קוד אימות לנייד, רואה רק את המפגשים בגן שלה, ומאשרת או מחזירה לתיקון |
| **רפרנטית (צוות אריאל)** | דשבורד, תור אישורים, חריגות ותקרות, ספקים וגנים, דוח חודשי, ייבוא וייצוא לאקסל, יומן פעולות והגדרות |

| רכיב | מצב |

## ארכיטקטורה
- **אפליקציה:** Next.js (App Router, TypeScript), מתפרסמת ב-Vercel מתיקיית `web/`.
- **מסד נתונים וכניסה:** Supabase (PostgreSQL 17 ו-Supabase Auth). הסקריפטים הממוספרים נמצאים ב-`database/postgres/`, ושינוי במבנה המסד נשמר כסקריפט חדש.
- **הדפדפן לא מדבר ישירות עם המסד.** כל הנתונים עוברים דרך השרת, וההרשאות נבדקות בשרת בכל עמוד.
- **הגנת שורות (RLS)** מופעלת בכל טבלאות האפליקציה, והגישה אליהן היא דרך השרת בלבד.
- **הודעות SMS:** הכניסה בנויה לשליחת קוד אימות ב-SMS. הספק שנבחר הוא 019, והחיבור ייעשה אחרי חתימת הלקוח. עד אז עובדים עם מספרי בדיקה.
- **תכנון מקורי:** בשלב האפיון תוכנן מסד SQL Server מקומי. סקריפטי ה-T-SQL בתיקייה `database/` נשארו כתיעוד של התכנון.

## כניסה ואימות

| משתמש | זיהוי | אימות |
|---|---|---|
| ספק | מספר ספק | קוד חד-פעמי לנייד הרשום |
| גננת | סמל גן | קוד חד-פעמי לנייד הרשום |
| צוות החברה | כתובת מייל | קוד חד-פעמי למייל |

אין סיסמאות. מוצגות רק הספרות האחרונות של הטלפון, הודעות השגיאה כלליות, ויש הגבלת קצב, פסילת קוד אחרי ניסיונות שגויים ונעילת נייד.

## אבטחת מידע
- הגנת שורות בכל הטבלאות, וגישה לנתונים דרך השרת בלבד.
- מדיניות CSP עם אסימון חד-פעמי לכל בקשה, וכותרות אבטחה.
- הגבלת קצב ונעילות, גם בשרת וגם במסד הנתונים.
- ניתוח קוד סטטי (CodeQL), עדכוני אבטחה לספריות (Dependabot) וגילוי סודות עם חסימת דחיפה.
- אימות דו-שלבי בחשבונות הניהול.
- בדיקת זמינות כל 15 דקות (`.github/workflows/uptime.yml`) והחרגת האתר ממנועי חיפוש.
- **הריפו ציבורי.** אסור להכניס אליו נתונים אמיתיים או סודות. נתוני הבדיקה פיקטיביים.

## על הדמו
- אב טיפוס אינטראקטיבי ([index.html](index.html) וקוד האפליקציה ב-[app.js](app.js)), בלי שרת ובלי התקנה. הקוד נמצא בקובץ נפרד כדי שמדיניות האבטחה (CSP) תאסור הרצת סקריפטים מוטמעים.
- הנתונים בדמו הם נתוני דוגמה, ונשמרים בדפדפן בלבד (localStorage).
- מותאם למחשב, לטאבלט ולנייד, בעברית מימין לשמאל, עם הגדרות נגישות.
- בדיקת כניסה: בוחרים תפקיד בראש המסך (ספק, גננת או רפרנטית), וכל קוד אימות מתקבל.

## פיתוח והרצה
הדמו: מספיק לפתוח את `index.html` בדפדפן.

האפליקציה החדשה:

```
cd web
npm install
npm run dev
```

נדרש קובץ `web/.env.local` עם שלושת משתני Supabase: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` ו-`SUPABASE_SERVICE_ROLE_KEY`. הקובץ לא נשמר בריפו.

## פריסה
שני פרויקטים ב-Vercel מאותו ריפו: הדמו מהשורש (`vercel.json`), והאפליקציה החדשה עם Root Directory בשם `web`. הכתובת `/web` בדמו מופנית לדף הבית. הקובץ `netlify.toml` שייך לאתר הדמו הישן ב-Netlify, שנשאר בינתיים.
