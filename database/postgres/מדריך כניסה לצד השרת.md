# מדריך כניסה לצד השרת (Supabase Auth)

המדריך מיועד למי שכותב את צד השרת (Next.js על Vercel, מתוך Claude Code).

## עקרונות

- **כל הגישה למסד היא מצד השרת**, עם מפתח `service_role`. המפתח הזה לא נשלח לדפדפן ולא נשמר ב-GitHub, רק במשתני הסביבה של Vercel.
- **אין הרשמה עצמית.** "Allow new users to sign up" כבוי. משתמש נפתח רק על ידי השרת.
- **מספר טלפון מלא לא יוצא מהשרת.** הדפדפן רואה רק טלפון מוסתר (050-***0201) של המשתמשים ששייכים לספק או לגן שהוקלד.
- **ספקים וגננות:** קוד SMS. **צוות אריאל:** קוד למייל בלבד.
- **חיבור השרת למסד:** הסכמות של המערכת (`core`, `ops`, `access` וכו') לא חשופות כרגע ב-Data API של Supabase. יש שתי דרכים: חיבור Postgres ישיר מהשרת (Connection pooler), או הוספת הסכמות ל-"Exposed schemas" בהגדרות ה-API. גם אם חושפים אותן, לתפקיד `anon` אין אליהן גישה.

## 1. פתיחת משתמשים (Provisioning)

כשמוסיפים גננת, איש קשר או איש צוות, או אחרי ייבוא מהאקסל, השרת עובר על הרשימה ופותח משתמשים:

```ts
const { data: pending } = await admin.schema('access').from('vw_pending_provisioning').select('*');
for (const p of pending) {
  if (p.phone) await admin.auth.admin.createUser({ phone: p.phone, phone_confirm: true });
  else         await admin.auth.admin.createUser({ email: p.email, email_confirm: true });
}
```

טריגר במסד (`trg_link_app_user`) מקשר אוטומטית את המשתמש החדש לגננת, לאיש הקשר או לאיש הצוות לפי הטלפון או המייל.
**שינוי טלפון של גננת:** צריך לעדכן גם את המשתמש ב-Supabase (`admin.auth.admin.updateUserById`).

## 2. כניסת ספק או גננת

| שלב | מה הדפדפן שולח | מה השרת עושה |
|---|---|---|
| א | סוג משתמש + מספר ספק / סמל גן | `access.login_options(user_type, login_key)` ומחזיר רק `option_id` וטלפון מוסתר |
| ב | `option_id` שנבחר | `access.resolve_login_phone(...)` ← טלפון מלא (נשאר בשרת). בודק `access.can_send_otp(phone)`. אם מותר: `signInWithOtp({ phone, options: { shouldCreateUser: false } })`, ורושם שורה ב-`ops.notifications` (purpose = 'OTP', destination בפורמט מקומי) |
| ג | הקוד שהוקלד | בודק `access.phone_locked_until(phone)`. אחר כך `verifyOtp({ phone, token, type: 'sms' })`. אם הקוד שגוי: `access.register_failed_attempt(phone)`. אם הצליח: `access.reset_failed_attempts(phone)` |
| ד | | `access.app_user(user.id)` ← סוג המשתמש, הגן / הספק שלו ותפקיד. שומרים בסשן |

`user_type` הוא `'SUPPLIER_CONTACT'` או `'TEACHER'`.

הודעות שגיאה כלליות בלבד ("פרטים שגויים"), כדי לא לחשוף אם מספר ספק או סמל גן קיימים.

## 3. כניסת צוות אריאל

`signInWithOtp({ email, options: { shouldCreateUser: false } })`, ואחר כך `verifyOtp({ email, token, type: 'email' })`.

לפני ייצור צריך להגדיר SMTP משלכם ב-Supabase. השירות המובנה מוגבל מאוד. אחרי ההגדרה עורכים את התבנית "Magic link or OTP" כך שתכלול `{{ .Token }}`.

## 4. אישור גננת על דיווח

בטבלה `ops.teacher_approvals` נשמרים `auth_user_id` ו-`auth_session_id` (ה-claim `session_id` מתוך ה-JWT), `phone_used`, כתובת IP, User-Agent ו-`content_hash` (SHA-256 של תוכן הדיווח).

## 5. היסטוריית שינויים

בתחילת כל טרנזקציה שמשנה נתונים:

```sql
SELECT set_config('app.actor', 'STAFF:12', true);
```

כך נשמר בטבלאות ההיסטוריה מי ביצע את השינוי.

## 6. סביבת בדיקות

הטלפונים הפיקטיביים 050-0000xxx מוגדרים ב-Supabase כ-Test Phone Numbers עם קוד קבוע, ולכן לא אמור להישלח SMS (לאמת בבדיקה הראשונה). ההגדרה בתוקף עד 28.2.2027.
את הקוד הקבוע מקבלים מהצוות. הוא לא נשמר בריפו.

## 7. עד שה-API של mgroup יגיע

ה-Send SMS Hook מפנה לפונקציה זמנית שמחזירה שגיאה. כניסה עם טלפון אמיתי תיכשל עם הודעה ברורה, ורק הטלפונים של סביבת הבדיקות יעבדו.
